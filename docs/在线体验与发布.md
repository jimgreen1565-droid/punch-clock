# 在线体验与发布

## 一、现在就能试（手机直接打开）

**线上地址：<https://jimgreen1565-droid.github.io/punch-clock/>**

- 手机浏览器（微信内也能开）直接访问，无需安装
- 首次打开会自动灌入一个月示例数据，可以直接点打卡、换规则、看统计
- **允许定位权限**后，它会取你当前位置与「打卡点」比较（默认打卡点在北京市中心，
  进去第一件事：点右上角规则胶囊 → 「打卡点坐标」→ 改成你自己所在位置）

> 它是 Web 版，和微信小程序共用同一套 `core/` 判定逻辑。
> 数据存在你手机浏览器的 localStorage 里，**不会上传到任何服务器**。

桌面预览（三栏样式，方便看全貌）：<https://jimgreen1565-droid.github.io/punch-clock/demo/>

### 手机上怎么把它变成"App 图标"

- **iPhone Safari**：打开 → 分享 → 「添加到主屏幕」
- **Android Chrome**：右上角菜单 → 「添加到主屏幕」

加完之后就是全屏无地址栏体验，和原生 App 几乎一样（这就是 PWA 的用法）。

## 二、发布成真正的微信小程序（要做的 5 步）

Web 版是"能立刻试"，但要做成微信小程序（能被搜索、能扫码、能用 `wx.getLocation`），必须过微信的流程。

### 1. 注册小程序账号

<https://mp.weixin.qq.com/> → 立即注册 → 选「小程序」

| 主体类型 | 是否需要认证 | 能否发布 | 说明 |
|---|---|---|---|
| 个人 | 免费，不需认证 | **能** | 但**不能用微信支付**、不能做需要资质的类目 |
| 企业 | 需微信认证（300 元/年） | 能 | 功能完整，可开支付 |

> 打卡小程序选「个人」主体就能跑起来，够用。类目选「工具 → 效率工具」或「办公」。

### 2. 拿到 AppID

注册完成后在「设置 → 基本设置」里能看到 AppID（形如 `wx1234567890abcdef`）。

### 3. 把 AppID 填进工程

打开 `project.config.json`，把 `"appid": "touristappid"` 改成你的真实 AppID：

```json
{
  "appid": "wx1234567890abcdef",
  ...
}
```

### 4. 用开发者工具上传

1. 下载 [微信开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)（稳定版）
2. 导入项目 → 选 `punch-clock/` 根目录
3. AppID 处填你的 AppID（或在 `project.config.json` 里已填好）
4. 点右上角**「上传」** → 填版本号（如 `1.0.0`）和项目备注
5. 上传成功后，到 <https://mp.weixin.qq.com/> → 「管理 → 版本管理」→ 找到刚上传的开发版本

### 5. 提交审核 → 发布

版本管理里点**「提交审核」**，需要填：

| 项 | 建议怎么填 |
|---|---|
| 功能页面 | 选 4 个主页面（打卡 / 记录 / 我的 / 考勤规则） |
| 测试账号 | 本地模式不需要登录，留空即可（若开了云开发要提供测试 openid） |
| 隐私协议 | 必须勾选「位置信息」——打卡要用 `wx.getLocation` |
| 类目 | 工具 → 效率工具，或 办公 → 办公工具 |

审核一般 **1-3 个工作日**。通过后在「版本管理」点**「发布」**，小程序就上线了，能被搜索、能扫码。

## 三、发布前必须补的两件事

这两件不是"可选优化"，是审核会卡或者用起来会出事的东西。

### 1. 用户隐私保护指引（必填，否则审核必拒）

微信要求所有涉及用户信息的接口都要申报。本项目用了 `wx.getLocation`，所以：

1. 后台「设置 → 服务内容声明 → 用户隐私保护指引」
2. 勾选「位置信息」
3. 用途描述写清楚，例如：
   > 用于核验打卡时员工是否位于考勤范围内。位置信息仅在打卡瞬间使用，不存储轨迹、不上传第三方。

不全填这一项，提交审核会被直接拒（提示「涉及用户隐私未声明」）。

### 2. 换成自己的公司坐标

默认打卡点是北京天安门坐标。上线前必须改：

**方式 A（推荐，不用改代码）**：小程序里进「考勤规则 → 打卡点坐标」，到公司门口点「把当前位置设为打卡点」。
配置存在用户自己手机上——注意这意味着**每个员工要自己设一次**。

**方式 B（团队用，配置集中）**：开通云开发，把坐标写进 `pc_configs` 集合（见 [部署与接入.md](部署与接入.md) §2.5），所有员工共享同一份配置。

> 团队使用必须走 B。否则每个人都能把打卡点设在自己家——那就不叫考勤了。

## 四、想给团队用，还需要什么

个人主体 + 本地模式 = 只能自己用（数据在各自手机上，谁也看不到谁的）。

团队用必须开云开发，才有：

- 统一的公司坐标/班次配置（管理员设一次，全员生效）
- 打卡记录上云（服务端授时 + 服务端算哈希，才真正防伪造）
- 管理端审批补卡、看异常、看汇总

步骤见 [部署与接入.md](部署与接入.md)，大致是：
云开发开通 → 填 `ENV_ID` → 建 6 个集合 → 部署 3 个云函数 → 把自己设成 admin。

## 五、常见卡点

| 现象 | 原因 | 处理 |
|---|---|---|
| 上传时报「AppID 不合法」 | 用了 `touristappid` 或填错 | 换成后台真实 AppID |
| 审核被拒「涉及用户隐私未声明」 | 没填隐私保护指引 | 见上文 §3.1 |
| 审核被拒「类目不符」 | 类目选错 | 改选「工具→效率工具」或「办公→办公工具」 |
| 真机定位一直失败 | 未在后台声明位置权限 | `app.json` 已声明；还需后台隐私指引勾选位置 |
| Web 版打开定位不动 | 不是 HTTPS 或用户拒了权限 | 线上地址是 HTTPS；检查浏览器权限设置 |
| Web 版换个手机数据没了 | 数据在 localStorage，不跨设备 | 这是设计如此（单机版），团队用请上云开发 |
