# 配色方案（为什么"单调"以及怎么改）

> 2026-10-31 追加。用户反馈"配色太单调"，第二版反馈（上一版是"太白"）。

## 诊断：单调的三个具体原因

不是"颜色不够多"，而是**色彩没有被用来编码任何信息**。

| 现象 | 原因 |
|---|---|
| 页面像白纸 | 只有 1 个蓝 + 灰阶。按钮、链接、选中态、数字全是一个色，没有深浅对比，眼睛找不到"强调"在哪里 |
| 记录列表满屏绿点 | 状态只有 6px 圆点。31 天里全是绿点，扫不出"哪天迟到、哪天缺卡"——信息没被编码，圆点就等于装饰 |
| 没有亮暗层次 | 页面纯白到底，没有任何区域比别的区域更亮或更暗，所以"平" |

## 三条改动

### 1. 顶部品牌浅色渐变带

```css
.shell {
  background-image: linear-gradient(180deg, var(--primary-soft) 0px, #ffffff 200px);
  background-size: 100% 200px;
}
```

页面上半部分带上品牌浅色，往下 200px 收敛到纯白。作用：给出"光从上面来"的层次，
让标题区不再是白纸上写字。**这是解决"平"最有效的一招**，因为它对应的是"页面有远近"。

### 2. 状态色扩到 6 个语义，异常类配浅底

| 状态 | 表达 |
|---|---|
| 正常 | 只有绿点 + 绿字（最轻，不抢戏） |
| 迟到 / 早退 | 琥珀浅底 + 同色字（能跳读） |
| 缺卡 / 旷工 | 红浅底 + 同色字 |
| 加班 / 外勤 | 主色浅底（**不用红黄**——它们不是问题） |

关键判断：**加班不该用警示色**。加班是"多干了"，不是异常，用红黄会让人误以为被批评。
用主色系既区分了类型，又不制造压力。

### 3. "今天"这一行给主色浅底 + 左侧竖条

记录列表里 31 行长得都一样，找不到今天。改成主色浅底 + `inset 3px 0 0 var(--primary)`
竖条后，一眼就能定位。

## 四套主题（`?palette=` 切换）

| 主题 | 主色 | 适合 |
|---|---|---|
| **blue**（默认） | `#2563EB` | 通用。最中性，不表达情绪 |
| **indigo** | `#4F46E5` | 更"设计感"，偏科技/研发团队 |
| **teal** | `#0F9D8F` | 清爽，和"早晨打卡"场景贴合 |
| **amber** | `#C2740C` | 暖，偏活力，适合门店/体力岗 |

线上直接对比：
`https://jimgreen1565-droid.github.io/punch-clock/?palette=blue|indigo|teal|amber`

## 两处配色冲突（改主题时必须处理）

改色不是替换一个变量就完事，有两处会撞：

1. **teal 主题下，"正常"的绿点会和主色太接近** → 加班标签和正常状态看起来是同一类。
   解法：teal 下把 `tag-ok` 的绿推深一档到 `#15803D`。
2. **amber 主题下，"迟到"的琥珀会和主色撞** → 异常标签失去警示作用。
   解法：amber 下把 `tag-warn` 推深到 `#8A3A0A` 并加大底色透明度。

这两条写在了 `palette.css` 里，是真实踩出来的。

## 为什么不上更多颜色

配色规范的 60-30-10 是硬约束：主色只能占 10%。想"更丰富"的正确做法不是加色相，
而是**把同一个色相拆成更多明度档**（浅底、主色、深色文字），再让状态色分工。

现在的分布：
- 60% → 白 + 顶部品牌浅色带
- 30% → 墨色文字 + 灰阶说明
- 10% → 主色（按钮、今天高亮、加班标签）+ 3 个状态色（只在小范围出现）
