# 背景方案排查：为什么"太白"不该用照片解决

> 2026-10-31 追加。用户反馈"太白了、有点单调"，问能不能网上找张图当背景。

## 结论先说

做了 4 个变体实测（对照图 `docs/bg-compare.png`）：

| 方案 | 效果 | 判断 |
|---|---|---|
| **A 现状（卡片式，纯白）** | 干净但确实单调 | 基线 |
| **B 照片头部 + 白色蒙版** | 照片只在打卡按钮周围露出一条，又脏又碎；下方内容压在繁忙照片上读不清 | **否决** |
| **C 极淡网格纹理** | 透明度提到 9% 仍然几乎看不出 | **否决**（无效工作量） |
| **D 扁平分组（去掉卡片边框）** | 留白更全、信息不碎、最耐看 | **推荐** |

线上可切换对比：`https://jimgreen1565-droid.github.io/punch-clock/?bg=N`

`N` = 0 纯白 / 1 照片浅蒙版 / 2 照片重蒙版 / 3 整屏照片 / 4 网格纹理 / 5 扁平分组

## 为什么照片方案失败了两次

**第一次**：蒙版只覆盖顶部 340px，下方照片裸奔。"正常 已上班"和两张卡片直接压在
照片纹理上——文字完全读不清，对比度掉到 3:1 以下。

**第二次**：把蒙版铺满整屏后文字可读了，但照片只在蓝圈周围露出一窄条。
既不构成氛围、又像图片没加载完。

**根因**：这个页面的信息密度不允许背景有存在感。背景要么"足够强"以至于干扰阅读，
要么"足够弱"以至于看起来像 bug——中间没有可用区间。

这也回答了"会不会好看"：**不会**。因为打卡页不是展示页，它没有一块足够大的
"安静区域"来承载照片。照片能好看的前提是页面有留白让它呼吸，而这里每一寸都要放信息。

## 真正的根因：不是颜色，是"卡片把整屏切成白块"

"太白"的感觉来自**白色面积太大又缺少层次**。而它恰好是"每个信息都装进等宽卡片"
这个做法的副作用：卡片边框 + 间距把页面切出一堆白块，视觉上反而更白、更碎。

## D 方案做了什么

- 去掉卡片边框、圆角、独立白底，改成**扁平分组**
- 用 32px 间距分组，用 1px 细线分隔组内行
- 只有打卡按钮和少量关键块保留一点体量感

效果：页面变成"一块连续的白 + 几根细线"。留白真正呼吸起来，信息也不碎了。

这跟钉钉/飞书打卡页当前的做法一致——两者都是扁平分组，没有卡片框。

## 如果还是想要图

唯一合理的用法是**给打卡按钮加一层极淡的纹理**（比如纸张/哑光质感），
作用是让它从纯色块变成一个"有材质的物件"，而不是铺满整屏。

这属于"点缀"级别，不能承载氛围。需要的话可以单独做一版对比。
