# 设计计划（对照 brief 的自我评审）

> 按 frontend-design 的流程：先出计划，再拿 brief 反驳自己，最后才写代码。
> 这份文档是给自己看的决策记录，也是别人评审时的依据。

## 0. Brief 是什么

一句话题目：**上班打卡 App 的主界面**。

- **谁用**：每天上班的人。一天开 4-6 次，每次停留 10 秒左右。
- **在哪用**：早上在写字楼下、电梯口、门口闸机旁。**经常在户外强光下**、单手、可能要赶时间。
- **它唯一的工作**：让人在 2 秒内确认「我该不该打卡 / 打了会怎样」，然后点下去。

这条 brief 里有两个词是关键约束，它们直接否掉了一批常见做法：

1. **"一天 4-6 次、10 秒"** → 这不是展示型页面。任何需要"读"才懂的设计都是失败。
2. **"户外强光"** → 深色主题在这里读不出来。这也是上一版深色被推翻的真实原因。

## 1. 先看 AI 默认会做成什么（用来避开的清单）

如果我不管 brief，随手做打卡 App，大概率会做成：

- 深色底 + 霓虹渐变圆按钮 + 外发光光晕（"科技感"套路）
- 大圆角（24-32px）+ 卡片投影 + 紫蓝渐变 hero
- 每个信息都塞进一个卡片，页面变成一叠等宽卡片
- 状态用红黄绿**大色块**标签

**上一版正好就是这样**：紫色渐变打卡按钮 + `filter: blur(40px)` 光晕 + 24px 圆角 + 卡片投影 + 彩色 tag 块。

所以这一版的动作是**把这些一个个删掉**，而不是"再优化一下"。

## 2. 设计计划

### 2.1 色彩（4 个命名值 + 语义色）

| token | 值 | 用途 |
|---|---|---|
| `--paper` | `#FFFFFF` | 页面底 |
| `--paper-2` | `#F7F8FA` | 次级底（分组、输入框） |
| `--rule` | `#E5E7EB` | 唯一的分隔手段（1px 细线） |
| `--ink` | `#111827` | 正文 |
| `--ink-2` | `#6B7280` | 次要说明 |
| `--ink-3` | `#9CA3AF` | 占位/禁用 |
| `--blue` | `#2563EB` | 唯一强调色（打卡按钮、当前选中） |
| 语义 | `#16A34A` / `#D97706` / `#DC2626` | 只做 ≤6px 圆点 |

**60-30-10 的落实**：白/灰占 60%，墨色文字 30%，蓝只出现在**打卡按钮一处**（加少量链接）。状态色全程只以 6px 小圆点出现，不铺底。

上一版有 6 个语义色 + 2 个渐变，这一版压到 1 个强调色 + 3 个点色。

### 2.2 字体与层级

单一字族：`-apple-system, "PingFang SC", ...`。**不引入第二款字体**——打卡界面上没有一个地方需要"装饰性排版"。

| 层级 | 规格 | 用在哪 |
|---|---|---|
| 页面标题 | 20px / 600 / 字距 -0.25 | 「10月31日」——全页唯一 H1 |
| 数据大字 | 28px / 600 / tabular-nums | 打卡按钮里的时钟 |
| 区块标题 | 16px / 600 | 卡片标题 |
| 正文 | 14px / 400-500 | 列表行、按钮 |
| 说明 | 12px / 400 | 应到时间、辅助说明 |

字重只有 400/500/600，**不用 700**。时间数字一律 `tabular-nums`，秒跳动时不抖动。

### 2.3 布局

左对齐为主（中文阅读习惯 + 扫读效率），只有打卡按钮区居中——因为它是唯一的"动作中心"。

```
┌─────────────────────────────┐
│ 考勤打卡              ⋯      │  ← 顶栏 14px/500，不抢位置
├─────────────────────────────┤
│ 10月31日          [固定班制] │  ← H1 + 规则入口（右侧胶囊）
│ 周六                          │
│ 09:00 - 18:00 · 周一至周五    │
│                               │
│         ╭───────────╮         │
│         │  08:52:14  │         │  ← 唯一视觉焦点：实心蓝圆
│         │  上班打卡   │         │     直径 184px（单手握得住）
│         │ 还需 9 小时 │         │     下方小字给"还剩多久"
│         ╰───────────╯         │
│           今天休息 / 正常      │
│                               │
│ ┌───────────────────────────┐ │
│ │ ● 上班 08:52   下班 --:--  │ │  ← 时间轴：一条细线串两点
│ │   应到 09:00   应到 18:00  │ │
│ ├───────────────────────────┤ │
│ │  45m      │    8h    │  —  │ │  ← 三格指标，等分
│ │ 已上(计时) │ 应满工时 │ 加班 │ │
│ └───────────────────────────┘ │
│                               │
│ ┌───────────────────────────┐ │
│ │ ● 公司  范围 300 米   已进入│ │  ← 打卡范围（状态只用一个绿点）
│ │ 距打卡点              14 米 │ │
│ │ [重新定位]   [外勤打卡]    │ │
│ └───────────────────────────┘ │
│                               │
│ 打卡记录写入本地哈希链…        │
├─────────────────────────────┤
│  ◷ 打卡    ☰ 记录    ○ 我的   │
└─────────────────────────────┘
```

**结构上的取舍**：

- **时间轴用一条 1px 线 + 两个 6px 点**，不是三个卡片。它是"一条时间线上两点"，用线表达比用卡片更准确。
- **指标三格不加边框、不加底色**，只靠一条竖 1px 分隔。它们是同一天的三个读数，不该看起来像三张卡。
- **规则入口做成右侧小胶囊**，不是大按钮。它一天最多点一次（改规则），不该和打卡按钮抢焦点。

### 2.4 三条原则（这一页靠什么变得不像模板）

1. **一个焦点**：全页只有一个实心蓝（打卡按钮）。其余所有"可点"的东西都是描边或纯文字。
2. **细线代替盒子**：能用 1px 分割线就不加卡片；能用小圆点就不加色块标签。
3. **说人话**：按钮下方给"还需 9 小时 14 分可下班"，而不是"剩余工时"。人关心的是**多久能走**。

## 3. 拿 brief 反驳自己

| 质疑 | 结论 |
|---|---|
| 大蓝圆按钮是不是也很像模板？ | 是"标准做法"，但 brief 明确是**高频单手操作**，圆的点击区最优、最不可能点偏。这里保留，理由来自交互不是审美。 |
| 全页只有一个强调色会不会太素？ | 打卡 App 的正确状态就是"素"。素才让"异常"显得重要——状态点上一个小橙点就足够跳。 |
| 20px 标题够不够抓眼？ | 够。这个 App 不需要"吸引人停留"，需要"快速确认后离开"。用 32px 大标题是营销页的做法。 |
| 时间轴那条线是不是装饰？ | 不是。它编码了"从上班到下班"的进度（`tl-line-fill` 按时间推进）。这是信息。 |
| 是不是又变成"一叠等宽卡片"了？ | 有风险。已缓解：时间轴/指标合成一张卡（同一件事），打卡范围单独一张（不同事），总共只有 2 张卡，不是 4 张。 |

## 4. 这一版具体删掉了什么

| 上一版 | 这一版 | 为什么 |
|---|---|---|
| 紫→蓝渐变打卡按钮 | 单一 `#2563EB` 实心 | 渐变是装饰，不表达信息 |
| `filter: blur(40px)` 光晕层 | 删除 | 纯装饰，且在浅底上只会脏 |
| 24px 圆角 + 卡片投影 | 12px 圆角 + 1px 边框 | 投影让页面发灰，边框更干净 |
| 彩色 tag 块（6 种底色） | 6px 圆点 | 状态色铺底会让"异常"失去信号强度 |
| 徽标/emoji 图标（`◷ ☰ ◯`） | SVG 单色 1.5px 描边 | 规范：禁止混 emoji；整套同风格 |
| 「应满工时 9h14m」+「还需在岗 9h14m」两处重复 | 只在按钮下方说一次 | 同一信息出现两次 = 噪音 |
| 休息日显示空时间轴（两条 `--:--` + 三条横线） | 一句「今天休息」说明 | 空占位是噪音，不是留白 |

## 5. 交付前自评（第 6 节清单逐条）

- [x] 没有"卡片+渐变底+大圆角按钮"默认首页 → 只有纯色圆按钮，无渐变
- [x] 没有"居中大标题+三张特性卡+CTA" → 结构是时间轴 + 指标 + 范围
- [x] 主色 ≤3 且符合 60-30-10 → 1 个强调蓝 + 灰阶
- [x] 状态色只做小圆点 → 6px
- [x] 字重只有 400/500/600，大标题负字距 → 遵守
- [x] 图标单色 + SVG + 同描边 1.5px → `icons.js` 统一生成
- [x] 圆角/字号/间距全站一致 → 6/8/12 三档，4 的倍数间距
- [x] 一页一个视觉焦点 → 打卡按钮
- [x] 留白够 → 板块间 24-32px
- [x] 文案具体 → “还需 9 小时 14 分可下班”、“本月已用 2/3 次补卡额度”
- [x] 状态/空态都处理 → 休息日空态、定位失败态、未定位态

**主动点名两处还能改的**（一次至少两处）：

1. **打卡按钮的尺寸**在 390px 宽屏上占 184px，页面还剩约 40% 空白。可以把时间轴收窄，或者把按钮略缩小到 168px 让卡片上移，减少一次滚动。
2. **统计页的日历**目前只用小圆点，10 月满月时有 31 个点，密集但不表达"这个月到底怎么样"。可以加一条极浅的"月历热力底"（按状态给 3 档灰蓝底），让人一眼看出哪几周崩了。
