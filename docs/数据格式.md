# 数据格式与哈希规则

> 目标：**让第三个人用任何语言（Python / Java / Go）都能独立实现同一套哈希，
> 并与小程序产生的记录互验**。照下面写的做，不需要跑我的代码也能验真。

## 1. 打卡记录字段字典

一条记录（`pc_punches` 或本地 `PC_RECORDS[i]`）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `uid` | string | 归属人。云模式=openid；本地模式=`U`+hash 前 12 位 |
| `dateKey` | string | **班次日**，`YYYY-MM-DD`（跨天班次可能不等于自然日） |
| `type` | `"in"` \| `"out"` | 上班 / 下班 |
| `at` | number | **服务端时间戳（ms）**。本地模式无服务端，等于 `clientAt` |
| `clientAt` | number | 客户端上报的时间戳，仅用于比对时钟偏差 |
| `source` | string | `miniprogram` \| `manual` \| `patch` \| `cloud` |
| `lat` / `lng` | number \| null | GCJ-02 坐标，保留 6 位小数参与哈希 |
| `acc` | number \| null | 定位精度（米），保留 1 位小数 |
| `dist` | number \| null | 距打卡点距离（米），保留 1 位小数 |
| `note` | string | 备注，≤60 字（外勤打卡必填原因） |
| `patchId` | string \| null | 补卡审批生成的记录会带来源 patch 的 id |
| `geoSkipped` | boolean | 是否未取到定位（参与哈希） |
| `seq` | number | 链内序号，从 1 开始，连续 |
| `prevHash` | string | 上一条的 `hash`；第一条为字符串 `"genesis"` |
| `hash` | string | 本条哈希，见 §2 |
| `createdAt` | number | 落库时间（≠ `at`，审批补卡时二者差很久） |

**不参与哈希的展示字段**：`shiftName`、`shiftId`、`wifiSsid`、`id`、`status`、
`lateMinutes`、`earlyMinutes`、`overtimeMinutes`、`hashFlags`、`geoReason`。
它们由规则引擎派生，属于"可重算"的冗余，改动不应让记录变成"被篡改"。

## 2. 哈希计算规则（可独立实现）

### 2.1 参与字段（固定 13 个）

```
uid, dateKey, type, at, clientAt, source, lat, lng, acc, dist, note, patchId, geoSkipped
```

### 2.2 归一化

| 字段 | 规则 |
|---|---|
| `lat` / `lng` | `round(x * 1e6) / 1e6` |
| `acc` / `dist` | `round(x * 10) / 10` |
| `at` / `clientAt` | `round(x)` → 整数 |
| `note` | 原样；空串保留 `""` |
| `patchId` | `null` 保留 `null` |
| `geoSkipped` | 布尔 |
| 其他缺省 | 一律 `null`（不是 `undefined`，不是省略） |

### 2.3 构造 payload

```
payload = stableJSON({ "prev": <prevHash 或 "genesis">, "rec": <归一化对象>, "v": 1 })
```

- **`stableJSON`** = key 按字典序（仅 ASCII 排序）递归排序后序列化的 JSON，无空格、无缩进。
  注意顶层是 `prev` / `rec` / `v` 三个键排序后的顺序（`prev` < `rec` < `v`）。
  Python 对应 `json.dumps(obj, sort_keys=True, separators=(',', ':'), ensure_ascii=False)`。
- 中文字符**不转义**（`ensure_ascii=False` / JS 原样）。这一条最容易踩坑。

### 2.4 求值

```
hash = SHA256_hex(payload)   // 小写十六进制，64 字符
```

### 2.5 一个可对照的样例

记录：

```json
{"uid":"U1","dateKey":"2026-10-30","type":"in","at":1793321820000,"clientAt":1793321820000,
 "source":"miniprogram","lat":39.90871,"lng":116.397412,"acc":22,"dist":96,
 "note":"","patchId":null,"geoSkipped":false}
```

生成的 payload（注意键已排序、无空格）：

```json
{"prev":"genesis","rec":{"acc":22,"at":1793321820000,"clientAt":1793321820000,"dateKey":"2026-10-30","dist":96,"geoSkipped":false,"lat":39.90871,"lng":116.397412,"note":"","patchId":null,"source":"miniprogram","type":"in","uid":"U1"},"v":1}
```

`hash = sha256(payload)`：

```
3b547a1908e12993a4e201c512a4b61b6d6ab613e189f59592b52ca192389b02
```

你可以拿这条记录去和小程序导出的 JSON 对比首条记录的 `hash`，或直接
`node -e "console.log(require('./miniprogram/core/ledger').hashOf(<record>,'genesis'))"` 复核。

### 2.6 Python 参考实现

```python
import json, hashlib

FIELDS = ["uid","dateKey","type","at","clientAt","source","lat","lng",
          "acc","dist","note","patchId","geoSkipped"]

def norm(rec):
    o = {}
    for k in FIELDS:
        v = rec.get(k, None)
        if k in ("lat","lng") and isinstance(v,(int,float)): v = round(v*1e6)/1e6
        elif k in ("acc","dist") and isinstance(v,(int,float)): v = round(v*10)/10
        elif k in ("at","clientAt") and isinstance(v,(int,float)): v = round(v)
        o[k] = v
    return o

def record_hash(rec, prev="genesis"):
    payload = json.dumps({"prev": prev, "rec": norm(rec), "v": 1},
                         sort_keys=True, separators=(",",":"), ensure_ascii=False)
    return hashlib.sha256(payload.encode("utf-8")).hexdigest()

def verify(records):
    prev = "genesis"
    for i, r in enumerate(records):
        if r["seq"] != i+1: return (False, i, "seq-mismatch")
        if (r.get("prevHash") or "genesis") != prev: return (False, i, "prev-hash-mismatch")
        if record_hash(r, prev) != r["hash"]: return (False, i, "hash-mismatch")
        prev = r["hash"]
    return (True, None, None)
```

> `round()` 的差异：Python 用银行家舍入（round-half-even），JS `Math.round` 是 round-half-up。
> 只有恰好落在 `x.5` 的坐标才有差异（概率极低）。要严格一致，把 `round(v*1e6)/1e6`
> 改成 `math.floor(v*1e6 + 0.5)/1e6`。

## 4. 考勤规则集（`PC_RULESET` / `pc_configs.ruleSet`）

```json
{
  "type": "fixed",                  // fixed | flexible | shift | free
  "name": "标准考勤组",
  "weekdays": [1,2,3,4,5],          // 1=周一 … 7=周日（ISO 口径）
  "start": "09:00", "end": "18:00", // fixed / shift（未开轮换时）
  "breakStart": "12:00", "breakEnd": "13:00",
  "lateGrace": 5, "earlyGrace": 5, "overtimeMin": 30,

  "latestStart": "10:00",           // flexible：最晚上班
  "earliestEnd": "17:30",           // flexible：最早下班
  "requiredMinutes": 480,           // flexible：每日应满工时

  "shifts": [                       // shift：班次定义
    {"id":"A","name":"早班","start":"08:00","end":"16:00","color":"#3b82f6"}
  ],
  "rotation": {                     // shift：周期轮换
    "enabled": true, "cycleDays": 4,
    "slots": ["A","A","B","REST"], "anchorDate": "2026-10-01"
  },

  "dailyTargetMinutes": 480,        // free：每日目标工时

  "geo": {"enabled":true,"strict":true,"radius":300,"lat":39.908823,"lng":116.39747,"name":"公司"},
  "wifi": {"enabled":false,"ssids":[]},
  "allowOutsideNote": true
}
```

`REST` 是排班里表示休息的特殊槽位值。

客户端与云端的 `normalizeRuleSet` 都会把非法值回落默认（非法 type → `fixed`，
全非法 `weekdays` → 周一至周五，超范围数字夹到边界）。

## 5. 本地存储键

| key | 内容 |
|---|---|
| `PC_BOOT` | `{uid, nickname, deviceId, env, createdAt}` |
| `PC_RULESET` | 当前考勤规则集（唯一权威配置） |

## 6. 日期与时间的口径（最容易出错的地方）

- **一律用固定 UTC+8**，不跟随手机时区。`dayKeyOf(ms)` 与 `partsOf(ms)` 都带偏移。
- **班次日 ≠ 自然日**：跨天班次（`end <= start`）时，凌晨打卡归前一天（见规则文档 §4）。
- **星期**：`1=周一 … 7=周日`（ISO 口径，不是 JS 的 `0=周日`）。
- **缺卡判定**：上班窗口后 120 分钟仍无 `in` → `missingIn`；下班窗口后 120 分钟仍无 `out` → `missingOut`。
  **休息日永不判定缺卡**。
- **旷工**：全天无任何记录且已过下班 2 小时 → `absent`。
- **出勤率** = 有上班卡的工作日 / 应出勤工作日（不是"正常天数/应出勤"）。
