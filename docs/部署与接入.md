# 部署与接入

## 0. 先确认你要哪种形态

| 形态 | 需要什么 | 数据在哪 | 适合谁 |
|---|---|---|---|
| **A. 纯本地（默认）** | 只要开发者工具 | 手机本地 storage | 自己用、演示、离线场景 |
| **B. 云开发** | 云环境 ID + 建集合 | 云数据库 | 团队打卡、需要管理端和防伪造 |

开箱是 A，随时可升 B，页面代码不用改。

---

## 1. 形态 A：本地模式（0 分钟）

1. 微信开发者工具 → 导入项目 → 选 `punch-clock/` 根目录
2. AppID：`touristappid`（测试号）或自己的
3. 编译

`miniprogram/utils/cloud.js` 的 `ENV_ID` 为空时 `cloud.init()` 返回 false，
所有页面自动走 `utils/store.js`（wx storage），功能完整：

- 打卡（四种规则、围栏、迟到早退/工时不足判定、缺卡/旷工）
- 记录（哈希链校验、补卡申请、手动补录、周历条、月份切换）
- 规则（四种类型切换、参数编辑、模板保存/应用）
- 统计（出勤率、异常分布、工时、近 7 日趋势）
- 我的（昵称、导出 JSON、清空）
- 管理（本地模式下只能看自己的数据）

初始化会灌入默认规则（固定班制 09:00-18:00）和示例打卡点（天安门坐标）。
**进去先去「考勤规则 → 把当前位置设为打卡点」改一下**，否则会一直提示超出范围。

## 2. 形态 B：云开发

### 2.1 开通并填环境 ID

开发者工具左侧「云开发」→ 开通 → 记下**环境 ID**（形如 `punch-prod-8gxxxxx`）。

`miniprogram/utils/cloud.js`：

```js
const ENV_ID = 'punch-prod-8gxxxxx'; // ← 改这里
```

### 2.2 建集合与索引

新建 6 个集合：

| 集合 | 用途 | 必需索引 |
|---|---|---|
| `pc_users` | 员工档案、角色 | `openid`（唯一） |
| `pc_punches` | 打卡记录（哈希链） | `openid`+`seq`（组合，唯一）；`openid`+`month`；`month` |
| `pc_configs` | 公司 / 规则集 / 围栏配置 | `companyId`（唯一） |
| `pc_patches` | 补卡申请 | `status`+`createdAt`；`openid` |
| `pc_rate` | 打卡频率计数 | `openid`+`action`+`at` |
| `pc_audit` | 审计留痕 | `at` |

`pc_punches` 的 `openid + seq` **组合唯一索引是必须的**：它保证两个人不串链、也不出现重复 seq。

### 2.3 权限

每个集合权限选 **「仅创建者可读写」**，然后所有业务读写都走云函数。
云函数用管理员权限不受这条限制；客户端直接读库会被拦住。
这样即使小程序包被反编译，也读不到别人的考勤。

### 2.4 部署云函数

```bash
node scripts/sync-shared.js
```

然后对 `cloudfunctions/login`、`punch`、`admin` 各右键 → **「上传并部署：云端安装依赖」**。

> 为什么必须先跑 sync-shared：云函数之间不能互相 `require`，每个函数目录必须自带一份 `common.js`。
> 忘了这步的典型报错：`Cannot find module './common'`。

### 2.5 初始化公司配置

在「云开发 → 数据库 → pc_configs」加一条：

```json
{
  "companyId": "default",
  "ruleSet": {
    "type": "fixed",
    "start": "09:00", "end": "18:00",
    "weekdays": [1,2,3,4,5],
    "lateGrace": 5, "earlyGrace": 5, "overtimeMin": 30,
    "breakStart": "12:00", "breakEnd": "13:00",
    "geo": { "enabled": true, "strict": true, "radius": 300, "lat": 31.230416, "lng": 121.473701, "name": "公司" },
    "allowOutsideNote": true
  },
  "geo": { "enabled": true, "strict": true, "radius": 300, "lat": 31.230416, "lng": 121.473701 },
  "allowSkipGeo": true
}
```

不建也能跑——云函数里有内置 fallback。
`ruleSet` 的完整字段见 [数据格式.md §4](数据格式.md)。

### 2.6 把自己升成管理员

第一次登录后 `pc_users` 里会有你的记录。把 `role` 从 `employee` 改成 `admin`。
之后「我的 → 审批与异常」里就能审批补卡、看异常和汇总。
同事的 `role` 可设 `manager`（能审批但不能改角色）。

## 3. 常见报错

| 报错 | 原因 | 处理 |
|---|---|---|
| `Cannot find module './common'` | 没跑 sync-shared | `node scripts/sync-shared.js` 后重新上传 |
| `-501000` / `env not exists` | ENV_ID 写错或环境未开通 | 核对环境 ID，确认账号有该环境权限 |
| `OUT_OF_RANGE` 但人就在公司 | 打卡点没设 / 半径太小 / 定位精度差 | 规则页「把当前位置设为打卡点」；或关掉严格模式改用外勤打卡 |
| `RATE_LIMITED` | 1 分钟内打卡 >5 次 | 等一分钟，这是防连点 |
| `FORBIDDEN` 打不开管理端 | 你的 role 不是 admin/manager | 数据库手改 `pc_users.role` |
| 哈希校验失败 | 有人直接改了数据库 | 看返回的 `brokenAt` 定位到第几条；用 `pc_audit` 追溯原始 hash |
| 真机上定位一直失败 | 未在小程序后台声明隐私接口 | `app.json` 已声明 `requiredPrivateInfos: getLocation`；还需在后台「用户隐私保护指引」勾选位置信息 |

## 4. 上线前检查清单

- [ ] `ENV_ID` 已填，三个云函数都部署成功
- [ ] 6 个集合已建，`pc_punches` 的 `openid+seq` 唯一索引已生效
- [ ] 集合权限为「仅创建者可读写」
- [ ] `pc_configs` 里的打卡点坐标和半径是真实值（用手机在门口实测一次）
- [ ] 至少一个人是 `admin`
- [ ] 小程序后台已配置「用户隐私保护指引」（位置信息）
- [ ] `geo.strict` 决策：严格（防代打卡）vs 宽松（防员工打不上卡）——多数团队选严格 + 允许外勤打卡
- [ ] 选定考勤规则类型（固定 / 弹性 / 排班 / 自由），并确认参数符合公司的真实制度
- [ ] 真机跑一遍：室内、室外、飞行模式（无定位）各打一次，确认三种情况提示都对
- [ ] 导出一次 JSON 备份，确认能留存

## 5. 灰度建议

团队 >20 人时，先只开 `manager` 审批流，观察一周的 `pc_audit`：

- `geoSkipped` 占比 >20% → 定位条件太苛刻，考虑放宽半径或改用 WiFi 辅助
- `timeSkew` 出现 → 有人手机时间不对（或有人在改时间），单独提醒
- `OUT_OF_RANGE` 集中在少数人 → 可能是外勤岗，给他们单独的 `companyId` 配置或改用自由工时
- 大量 `under`（工时不足）→ 弹性班的 `requiredMinutes` 设太高，或午休时长配错
